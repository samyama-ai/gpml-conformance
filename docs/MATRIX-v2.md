# Suite v2 — the construct matrix

Status: design, frozen before any v2 cell is run. Supersedes nothing; v1's 17 constructs
are retained verbatim so the v1 numbers stay comparable.

## Why widen

v1 picked 17 constructs by hand. Each one is defensible on its own and the set is not:
a reader cannot tell what was left out, or whether the 17 were the ones that happened to
disagree. "Seventeen queries" is also not what a vendor means by conformance.

v2 replaces hand-picking with **enumeration over declared dimensions**. Every cell is
generated by a rule, so the matrix states its own coverage and its own gaps. Where a
dimension is not enumerated, the reason is written down here rather than left implicit.

## What the oracle already supports

`src/gpml_ref.py` is more general than the v1 suite that calls it. Without changing a
line of the reference semantics it already evaluates:

| Capability | In v1 suite | Available |
|---|---|---|
| restrictor x selector, all 16 combinations | 6 of 16 | yes |
| quantifier bounds, including `{0,0}` and unbounded | 4 forms | yes |
| **two or more concatenated quantified segments** | **0 cases** | yes |
| direction `->`, `<-`, `-` | 3 cases | yes |
| node and edge predicates inside a segment | 1 case | yes |
| edge label disjunction | 0 cases | yes |
| undirected edges | 0 cases | yes |

The single largest v1 gap is multi-segment patterns: the standard's own worked example
(Deutsch et al. Sec. 5.1) is a two-segment pattern, and no v1 case has more than one
segment. Restrictor scope — whether the restrictor applies to the whole path pattern or
to each segment — is only observable with two segments.

## Dimensions

### G1 — the restrictor x selector grid

All 4 restrictors x all 4 selectors, on two fixtures, with a bounded quantifier.
**32 cells.**

- restrictors: none (WALK), TRAIL, ACYCLIC, SIMPLE
- selectors: ALL, ANY, ALL SHORTEST, ANY SHORTEST
- fixtures: `micro` at `{1,4}`, `fig1` at `{1,3}`

`micro` (`a =e1,e2=> b -e3-> c -e4-> a`) separates every pair on its own:

| separation | witness |
|---|---|
| WALK vs TRAIL | at 4 hops `e1,e3,e4,e1` repeats `e1` |
| ACYCLIC vs SIMPLE | `a,e1,b,e3,c,e4,a` returns to the start |
| ALL vs ALL SHORTEST | 1-hop and 4-hop paths share endpoint pairs |
| ALL SHORTEST vs ANY SHORTEST | `e1` and `e2` are two shortest paths `a`->`b` |

`fig1` is the standard's own Figure 1 Transfer graph, so the second half of the grid is
run on the graph the specification itself uses.

A grid is the point: 16 combinations is the whole of the restrictor-selector space the
standard defines, so coverage of that space is 100% by construction rather than by
assertion.

### G2 — quantifier forms

Quantifier x restrictor, selector fixed to ALL, fixture `micro`. **14 cells.**

Forms: no quantifier, `{0,0}`, `{0,1}`, `{1,1}`, `{1,3}`, `{0,3}`, `{2,4}`.
Restrictors: WALK and TRAIL (the pair that the forms actually separate).

Unbounded forms (`*`, `+`, `{2,}`) do not appear here. Under WALK with a non-shortest
selector they have no finite reference answer, and the standard forbids the `ALL` case
outright — so they are a well-formedness question, not an answer question, and they move
to G4.

### G3 — pattern shape

Shape x restrictor {WALK, TRAIL}, selector ALL. **16 cells.**

| shape | what it isolates |
|---|---|
| single segment (control) | baseline |
| two concatenated quantified segments | restrictor scope: whole pattern or per segment |
| segment with an interior node predicate | whether the quantifier binds the node pattern |
| direction `<-` | reverse traversal |
| direction `-` on directed edges | whether an undirected step may re-cross its own edge |
| self-loop fixture | one edge and one node, both repeated |
| 2-cycle fixture | separates WALK from TRAIL using forward edges only |
| parallel edges | two edges with the same endpoints are two paths |

**Dropped from this group, with the reason.** Edge label disjunction `[:E|F]` and
undirected edges both need a second edge label or a second edge kind in the loader, and
every adapter registers exactly one. Changing that touches ten adapters to measure two
constructs, and several engines have no undirected edge type at all. Declared as a gap.

### G4 — what the standard requires to be *rejected*

Conformance is not only which answers come back. The standard makes some patterns
ill-formed, and an engine that runs them is non-conforming in the other direction — a
direction no prior work measures and v1 did not either. **6 cells**, scored on a
different verdict set:

| case | rule |
|---|---|
| `*` with no restrictor and selector ALL | Sec. 5: an unbounded quantifier must be in the scope of a restrictor or a selector |
| `+` with no restrictor and selector ALL | same |
| `{2,}` with no restrictor and selector ALL | same |
| `*` under TRAIL | well-formed; must be accepted. The control that stops this grid being all-reject by construction |
| `*` with ANY SHORTEST, no restrictor | well-formed; must be accepted |
| selector applied before restrictor | Sec. 5.1: "selectors are always applied after restrictors" — observable where the two orders give different answers |

Verdicts here are `REJECTS` (correct for an ill-formed case), `ACCEPTS` (a divergence for
an ill-formed case, conformance for a well-formed one), and `INEXPRESSIBLE`. The control
rows matter: a grid where every case must be rejected would be passed by an engine that
rejects everything.

### G5 — v1 retained

All 17 v1 constructs are kept with their ids unchanged. Cells that G1-G3 regenerate are
reported once and cross-referenced, not double-counted.

## Surface spellings

One construct, four spellings, and an engine parses one of them. The runner asks each
engine which it takes (`src/capabilities.py`) rather than deciding from a hardcoded list.

| rendering | shape | who takes it |
|---|---|---|
| `cypher` | `-[:E*1..3]->`, no restrictor or selector keyword | every openCypher engine |
| `cypher_gql` | the same, with the standard's prefixes | ArcadeDB, Samyama |
| `cypher_qpp` | `(()-[:E]->()){1,3}` with the prefixes | Neo4j 2026.04 |
| `gql` | `-[:E]->{1,3}` -- the standard's own spelling | SurrealDB |
| `pgq` | `GRAPH_TABLE(... MATCH ...)` | DuckPGQ |

## What stays out, and why

- **Performance of any kind.** Unchanged from v1. This is a semantics measurement.
- **Writes, transactions, DDL, aggregation, subqueries.** Out of the path core.
- **Counted selectors (`ANY k`, `SHORTEST k`).** GQL defines them; the reference
  exposition's Fig. 8 does not, and our oracle does not implement them. Adding them means
  extending the oracle, which is a separate piece of work with its own Gate B. Declared as
  a gap rather than quietly omitted.
- **Patterns with alternation or optional segments.** Same reason.

## Traceability

Every case carries a `clause` field naming the specific rule it tests — a section or
figure of Deutsch et al. (arXiv:2112.06217) and, where it differs, the ISO clause. A case
with no clause is not a conformance case and the harness refuses to run it.

## Engines not in the matrix, and why

Named here so the absences are declared rather than silent.

| engine | blocker |
|---|---|
| LadybugDB 0.21.2 | The live MIT fork of Kuzu, whose own row is frozen for good. The adapter is written and works in isolation; the wheel resolves its C API shared library through a separate download step (`LBUG_C_API_LIB_PATH`) that fails once `kuzu` is imported in the same process. Fixable by running that row in its own process, which the harness does not yet do. |
| Oracle Database 23ai Free | The only free local SQL/PGQ besides DuckPGQ. ~9 GB on disk and documented as having no path modes and no selectors, so it is a breadth row rather than an insight row. |
| Amazon Neptune, BigQuery Graph | No free offline runtime at any price. Cloud endpoints only. |
| TigerGraph, NebulaGraph OSS, ArangoDB, SAP HANA, AnzoGraph, Aerospike | No path modes, no selectors, and in several cases a licence key or a commercial-use restriction. |
| Ultipa GQLDB | The widest published GQL conformance claim of any vendor, including a per-feature table and a stated TRAIL default. No Docker image; installs through a shell script. Worth the effort next. |
